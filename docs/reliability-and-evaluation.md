# 索引可靠性、登录与评测

## 索引写入与删除

文档更新先为新版本生成 UUID，把向量和 ES 切片暂存。两个索引都写入成功后，后端在同一个 PostgreSQL 事务中替换切片、更新原文与计数，并将 `knowledge_document.index_revision` 切换到新版本。准备或提交失败时只清理新版本，旧内容和旧索引继续可用。

检索在召回之前读取业务表允许的文档及活跃版本。软删除文档或知识库即刻停止新请求的召回，即使外部索引清理暂时失败也不会再次暴露。失败清理会记录日志；旧的无版本索引兼容读取，重建后自动失效。遗留的无版本切片及异常退出产生的暂存版本可能仍占用存储，但不会占用召回名额。

知识库锁统一串行化文档提交、文档删除及知识库删除。文档更新还检查版本与更新时间，过时提交返回 409。文档计数包括索引失败但尚未删除的文档；切片数只统计已提交切片。

## 登录与权限

所有业务 API 使用全局 JWT 守卫，只有登录、注册和根健康响应公开。浏览器登录使用 HttpOnly、SameSite=Strict Cookie；API 和 SSE 均使用 `/api` 同源地址。知识库、文档、会话和消息操作同时检查用户归属，事件流通过请求上下文绑定用户。

生产环境必须设置随机 `JWT_SECRET`，并经 HTTPS 访问，以便发送 Secure Cookie。开发环境未配置密钥时使用进程级随机密钥，后端重启后重新登录。可以在登录页直接注册账号；原有默认用户 ID 回退已移除。

本次新增迁移仅增加 nullable 字段，不删除现有表或向量：

```sh
pnpm db:deploy
```

初始迁移中遗留的旧聊天表仍保留，避免删除历史数据；当前代码使用 JSONL 会话。不要通过重置数据库解决已有环境的迁移差异。

## 检索与解析

向量与 BM25 并行召回。单路失败时记录错误并使用存活结果；两路都失败时报告服务不可用，不把服务故障当作“没有答案”。查询作用域显式为空时直接返回空结果。

表格和正文切片按原文顺序产生。全文预览读取保存的原文，避免重叠切片拼接造成重复。PDF/Markdown/TXT 没有提取到文本时返回 400，不将原始二进制内容写入索引。临时文件使用独立随机目录并异步清理。

## 评测口径

- `HitRate@k`：正常问题中至少一个标注证据命中的比例。当前标注以文档名、文本段落或关键词匹配，不能称为完整证据 Recall。
- `MRR`：第一个命中证据的倒数排名。
- `firstHitDcg`：第一个命中证据的折扣增益，不是多相关项 nDCG。
- 陷阱题：检索层只记录召回数量，不判定幻觉，不计入正常题指标均值。生成层规则评测仅作粗筛；最终回答是否正确拒答、是否包含无依据断言，需单独审核。
- Ragas 汇总排除陷阱题；关键词拼接 reference 的 ContextRecall 只作粗略诊断。历史报告保留原样，新报告不能直接与旧口径混用。

未重新调用外部模型生成全量评测报告，也没有据此宣称回答质量已提升。后续重排序或切片参数实验应固定语料、标注及模型配置。

## 验证

```sh
pnpm typecheck
pnpm lint
pnpm test
pnpm --filter @langchain-rag/frontend build
```

集成测试需要本地 PostgreSQL（含 pgvector）和 Elasticsearch（含 smartcn）。示例地址请按实际映射端口调整：

```sh
INTEGRATION_DATABASE_URL=postgresql://root:chenjiang@localhost:5433/postgres \
ES_URL=http://localhost:9200 pnpm test:integration
```

脚本新建 `codex_rag_test_*` 数据库与同名前缀 ES 索引，从仓库迁移初始化，使用本地模拟 embedding 服务验证真实 HTTP、登录 Cookie、跨用户拒绝访问、版本切换、失败回滚、删除计数和空文本解析。完成后只清理脚本自己创建的资源，不连接外部模型。
